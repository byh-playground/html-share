# HTML Share UX 원칙

## 저장소에서 역할 찾기

루트에는 `share.ps1` 실행 진입점, 저장소 문서와 공통 설정을 둡니다. 서비스 코드는 `src/` 아래에서 서버, 프로젝트 파일 처리, 관리, PWA, 알림으로 구분합니다. 독립 실행 도구는 `scripts/` 아래에서 터널, 공유, PWA 설정, 개발 도구로 구분하고 테스트는 `tests/`에 영역별로 배치합니다.

새 파일은 이름만 보고도 역할을 알 수 있게 짓고, 같은 관점의 기능이나 도구는 해당 폴더에서 함께 관리합니다. 내부 폴더를 바꾸더라도 사용자 명령 `share.ps1`과 개인 데이터 경로는 유지합니다.

## 명령과 도움말

README, 변경 기록, 보안 안내, 사용 가이드 등 공개 문서는 한글을 기본으로 작성합니다. 명령어·파일명·API 이름·제품명은 원래 표기를 유지하되, 제목과 설명 문장은 한글로 작성합니다. README는 저장소 정보 중심으로 유지하고 자세한 사용 절차는 HTML 사용 설명서와 상세 가이드에 반영합니다.

사용자가 매번 질문하지 않아도 되도록 `share.ps1 help`와 PowerShell 기본 도움말을 **한글로 유지**합니다. 명령·옵션을 추가하거나 변경할 때 사용 가능 조합, 기본값, 예시, 재발급·삭제 같은 중요한 결과까지 도움말과 README에 함께 반영합니다. 명령 또는 옵션이 도움말에서 빠지면 회귀 테스트가 실패하도록 유지합니다.

## 핵심 사용 흐름

이 도구의 주요 반복 작업은 **HTML 선택 → 업로드 완료 → 해당 페이지 열기 → 동작 확인·디버그 → 관리 화면으로 돌아와 수정본 재업로드**입니다.

- 기본 작업 영역은 프로젝트 선택, 현재 적용 파일, 파일 선택, 업로드 행동 순서입니다.
- 업로드 후 바로 열기는 클릭할 때 대기 탭을 열고, 성공 응답을 받은 뒤 그 탭에서 페이지를 표시합니다. 확인 후 기존 관리 탭으로 돌아와 수정본을 올립니다. 업로드만 하기는 관리 화면에 남습니다.
- 팝업이 차단되거나 사용자가 대기 탭을 닫아도 업로드는 계속됩니다. 성공하면 완료 카드의 지금 페이지 확인 링크로 새 탭에서 열 수 있습니다. 오류·취소·불완전한 응답에서는 페이지를 열지 않고 관리 화면에서 결과를 확인합니다.
- 프로젝트 확인 URL에는 관리 경로나 인증 키가 포함되지 않습니다. 공개 페이지에 관리 화면으로 돌아가는 링크를 삽입하지 않습니다.
- 최근 프로젝트는 관리 주소의 fragment에 기록합니다. 등록된 관리 키는 그대로 유지하며 별도 브라우저 저장소에 복사하지 않습니다.

## 기존 기능 유지

상단의 프로젝트 선택을 전체 화면의 공통 컨텍스트로 사용합니다. 탭 제목·완료 카드·파일 수 요약·공유 카드에서 같은 프로젝트명을 반복하지 않습니다. 각 탭은 업로드, 적용, 설정, 공유라는 작업 자체를 표현합니다. 실제 파일명·공유 URL·PWA 앱 이름처럼 필요한 데이터는 그대로 표시합니다.

모바일 기본 화면은 공통 프로젝트 카드와 하단 4개 탭으로 구성합니다. 업로드·적용 관리·PWA 설정·공유를 한 번에 모두 길게 보여주지 않고, 선택한 작업의 카드만 표시합니다. 내용이 긴 PWA 설정이나 파일 목록은 해당 탭 안에서 자연스럽게 스크롤합니다.

탭 이동은 입력 상태를 초기화하지 않습니다. 선택한 파일과 미저장 메타정보를 유지하며, 미저장 표시와 최근 탭 복원을 제공합니다. 탭은 키보드 좌우·Home·End와 ARIA tab/tabpanel 상태를 지원합니다. 모바일 하단 안전 영역과 화면 키보드·작은 화면의 스크롤을 고려합니다.

기존의 업로드만 하기, 새 탭으로 프로젝트 열기, ZIP 처리, PWA 체크·메타정보 저장, 설정과 업로드 동시 실행, 적용 목록, 이전 파일 재적용, 정리 확인, 공유 QR, 선택 ntfy 기능을 유지합니다.

**기존 기능을 제거하려면 구현 전에 사용자에게 무엇을 없애고 왜 필요한지 제안해 확인받습니다.** 자주 쓰는 흐름을 개선한다는 이유만으로 덜 쓰는 기능을 임의로 제거하지 않습니다.

## 확인과 디버그

관리 화면 상단에서 적용 중인 파일과 PWA 빌드를 확인하고, 업로드 완료 카드에서 저장된 파일·빌드·시간을 확인합니다. 프로젝트 페이지의 개발자 도구나 앱 자체 디버그 기능은 그대로 사용합니다.

새 요청 식별자는 이전 탐색과 구분하기 위한 것으로, 브라우저 캐시 전체 삭제나 앱 서비스 워커 해제를 보장하지 않습니다. 운영 중인 PWA를 깨뜨리는 강제 초기화는 기본 동작으로 넣지 않습니다.
