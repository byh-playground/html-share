# HTML Share 사용 가이드

전체 명령·옵션은 `.\share.ps1 help`에서 **한글**로 확인하세요. `.\share.ps1 -Help`, `.\share.ps1 -h`, `Get-Help .\share.ps1 -Full`도 지원합니다. 도움말은 서버 실행이나 설정 변경 없이 표시됩니다.

기본 흐름은 **터널 제공자 선택·연결 → 비공개 관리 QR 스캔 → 관리 페이지에서 업로드·설정 → 프로젝트 링크 또는 공유 QR 전달**입니다. ntfy는 선택 기능입니다.

## 처음 한 번 준비하기

저장소 폴더에서 PowerShell을 열고 실행합니다.

```powershell
.\share.ps1 setup
.\share.ps1 doctor
.\share.ps1 start
```

Node.js 22.17 이상이 필요합니다. `setup`은 npm 잠금 파일에 맞는 의존성과 선택한 터널을 준비합니다. 제공자를 선택한 적이 없으면 ngrok을 사용합니다.

선택 이력이 없으면 ngrok이 기본값입니다. ngrok으로 처음 `start -Provider ngrok`하면 ngrok 인증 페이지가 열립니다.

1. ngrok 계정으로 가입하거나 로그인합니다.
2. 대시보드에서 **Your Authtoken**을 찾습니다.
3. 토큰 값만 복사합니다. API Key나 명령 전체를 복사하지 않습니다.
4. PowerShell 창에 붙여넣고 Enter를 누릅니다. 입력 글자가 보이지 않는 것은 정상입니다.
5. 공개 주소와 비공개 관리 QR이 나타나면 연결 완료입니다.

[Your Authtoken 페이지](https://dashboard.ngrok.com/get-started/your-authtoken)

토큰은 `.runtime/ngrok.yml`에 저장되며 이후에는 다시 입력하지 않습니다. ngrok 인증을 바꾸려면 `.\share.ps1 configure`를 사용합니다. 이 ngrok 토큰과 휴대폰 관리 인증 키는 서로 다른 정보입니다.

## Cloudflare Quick Tunnel로 임시 전환하기

ngrok 한도로 외부 접속이 막혔거나 계정 없이 공유하려면 다음과 같이 실행합니다.

```powershell
.\share.ps1 ntfy                        # 알림 켜기. 기존 토픽이 있으면 그대로 재사용
.\share.ps1 start -Provider cloudflare  # 실행 중인 ngrok에서 바로 전환 가능
```

Cloudflare 계정·인증·도메인 구매는 필요 없습니다. 필요한 cloudflared는 `start`에서 자동 설치합니다. 미리 설치하려면 `.\share.ps1 setup -Provider cloudflare`를 사용하세요. 처음 ntfy를 설정했다면 구독 QR을 휴대폰에서 스캔해야 알림을 받을 수 있습니다.

- 공개 주소는 임의의 `trycloudflare.com` 도메인입니다. 로컬 서버·프로젝트 원본·관리 인증 키는 전환하면서 유지됩니다.
- 제공자 선택은 `.runtime/tunnel-settings.json`에 저장됩니다. 다음부터 `start`만 실행하면 Cloudflare를 다시 사용합니다.
- 감독 프로세스가 cloudflared의 종료를 감지하면 자동으로 다시 실행합니다. 새 URL이 생기면 ntfy로 최신 링크를 보내고 실패한 알림은 재시도합니다. 프로세스가 유지되는 동안 같은 URL로 연결만 복구되면 알림을 반복하지 않습니다.
- ntfy는 여전히 선택 기능입니다. 주소 알림에는 `-Updates`가 필요하지 않고, `ntfy -Disable`이면 전송하지 않습니다.
- 관리 키를 회전시키지 않습니다. 도메인이 바뀌면 전체 관리 URL도 달라지므로 새 알림을 이용하거나 `manage`·`qr`로 현재 URL의 QR을 다시 만드세요.
- 예전 도메인으로 설치한 PWA는 그대로 남습니다. 새 링크를 브라우저로 열어 사용하세요. 주소가 달라지면 저장소·서비스 워커·설치 앱이 별개이며 앱 내부 데이터는 자동 이전되지 않습니다.
- Cloudflare 업로드 한도는 요청당 100 MB입니다. 큰 ZIP은 PC에서 `manage -Local`로 올릴 수 있습니다. 서버 자체의 파일 한도도 그대로 적용됩니다.

ngrok 한도가 초기화되면 직접 복귀합니다. 자동으로 복귀하는 일정은 없습니다.

```powershell
.\share.ps1 start -Provider ngrok
```

이후 기본 `start`도 ngrok을 사용합니다. `stop`은 로컬 서버와 Quick Tunnel 감독 프로세스·cloudflared를 함께 종료합니다. Quick Tunnel은 임시 공유용이므로 고정 주소와 가용성을 보장하지 않습니다.

## 내 휴대폰 연결

PC에서 로컬로 업로드·관리하려면 다음 명령을 사용합니다. ngrok 전송량을 소모하지 않으며 기존 외부 관리 링크는 그대로 유지됩니다.

```powershell
.\share.ps1 local          # 서버가 이미 실행 중이면 그대로 사용
.\share.ps1 manage -Local  # 출력된 로컬 관리 주소를 PC 브라우저에서 열기
```

로컬 루트 `http://127.0.0.1:8787`은 프로젝트 목록입니다. 업로드는 키가 포함된 별도 관리 주소로 접속하세요.

휴대폰 기본 카메라로 PC의 **PRIVATE management QR**을 스캔하세요. ngrok 안내가 나오면 **Visit Site**를 누릅니다. 별도 알림 앱 설치 없이 인증된 통합 관리 화면으로 들어갑니다.

```powershell
.\share.ps1 manage   # 현재 비공개 관리 링크와 QR
.\share.ps1 qr       # 비공개 관리 QR 다시 보기
```

QR 이미지는 `.runtime/manage-qr.png`에도 저장됩니다. 관리 링크를 즐겨찾기에 저장하면 이후에는 다시 스캔할 필요가 없습니다.

- 인증 키와 비공개 경로는 재시작해도 유지됩니다.
- 도메인까지 유지하면 전체 관리 링크도 같습니다.
- 관리 QR과 링크는 소유자만 보관합니다. 이를 가진 사람은 업로드·적용·정리가 가능합니다.
- 외부 공유가 실행 중일 때 휴대폰 QR을 생성합니다. `127.0.0.1`은 휴대폰에서 서버 PC를 가리키지 않습니다.
- 이전 버전의 `/upload/#key=...` 관리 링크는 폐기되었습니다. `manage` 명령으로 새 경로를 한 번 받아 저장하세요. 기존 인증 키를 재발급하는 것은 아닙니다.

### 관리 화면에서 다른 내 기기 연결

이미 연결한 휴대폰이나 PC에서 **공유 탭 → 내 기기 연결 → 관리 QR 보기**를 누릅니다. 다른 본인 기기로 스캔하면 같은 관리 화면이 열립니다. **관리 링크 복사**로 기존 링크를 전달할 수도 있습니다.
인증 키나 주소를 새로 발급하지 않습니다. QR은 평소에는 숨겨져 있고 버튼을 눌렀을 때만 표시되며, 닫으면 이미지와 링크 표시를 지웁니다. 로컬 `127.0.0.1` 주소에서는 다른 기기로 연결되지 않으므로 공개 공유 주소의 관리 화면에서 사용하세요.
방문자용 **페이지 공유**와 본인용 **내 기기 연결**을 구분하세요. 관리 QR에는 업로드·정리 권한이 포함됩니다.

## 프로젝트 만들고 파일 올리기

프로젝트 폴더는 PC의 `public` 아래에 먼저 만듭니다.

```text
public/
├─ my-project/
│  ├─ 이전버전.zip
│  └─ 새버전.zip
└─ example/
   └─ hello.html
```

루트 페이지는 프로젝트 목록만 보여줍니다. 관리 화면은 공개 폴더 밖의 `src/management/ui/`에서 제공하며, 공개 목록에서 들어가는 링크가 없습니다.

관리 QR로 연결한 뒤:

1. 대상 프로젝트 선택
2. HTML·HTM 또는 ZIP 선택
3. **업로드 후 페이지 열기** 클릭
4. 저장 완료 후 새 탭에서 해당 페이지 확인·디버그
5. 기존 관리 탭으로 돌아와 같은 프로젝트에 수정한 파일을 다시 업로드

**업로드 후 페이지 열기**는 클릭할 때 대기 탭을 열고, 저장이 완료되면 그 탭에서 페이지를 표시합니다. 팝업이 차단되거나 대기 탭을 닫아도 업로드는 계속됩니다. 업로드가 성공하면 관리 화면의 **지금 페이지 확인** 링크로 새 탭에서 열 수 있습니다.

**업로드만 하기** 버튼은 기존처럼 관리 화면에 남습니다. 완료 카드를 위쪽에 표시하고 저장 파일·PWA 빌드·적용 시간을 보여줍니다. **지금 페이지 확인**과 **새 탭에서 열기**는 모두 새 탭에서 엽니다. **수정한 파일 다시 선택**으로 다음 반복을 시작할 수 있습니다.
프로젝트 선택 바로 아래에 현재 적용 파일과 빌드를 표시합니다. 모바일 하단에는 **업로드 / 적용 관리 / PWA 설정 / 공유** 탭이 있습니다. 업로드 작업은 업로드 탭에서, 메타정보는 PWA 설정 탭에서 다룹니다. PWA 설정을 작성한 뒤 업로드 탭으로 돌아와 설정 저장과 업로드를 함께 진행하는 기능도 유지합니다.
선택한 파일과 미저장 PWA 설정은 탭을 옮겨도 유지됩니다. 탭·프로젝트는 새로고침과 뒤로 가기 후 복원됩니다. 적용·전송 중에는 다른 작업으로 전환하지 않도록 탭이 잠시 비활성화됩니다.
페이지 확인 링크에는 새 요청을 위한 식별자가 붙지만, 앱 자체의 캐시를 삭제하거나 서비스 워커를 강제로 해제하지는 않습니다.

같은 이름의 파일은 `파일명-1.html`처럼 새 이름으로 보관하며 원본을 덮어쓰지 않습니다. 전송이 끝난 파일만 게시됩니다. ZIP은 검사 후 자동으로 풀립니다.

일반 프로젝트에서는 수정일이 최신인 HTML/HTM 또는 ZIP을 적용합니다. 동률이면 ZIP이 우선합니다. ZIP을 여러 개 합쳐 풀지 않습니다. 새 파일을 올리면 같은 프로젝트 주소에 반영됩니다.

업로드 한도는 파일당 256 MiB입니다. ZIP은 파일 하나 128 MiB, 추출 합계 512 MiB, 5,000개 항목 제한도 적용합니다. 손상·암호화·위험 경로가 있는 ZIP은 거절합니다. 여러 자원을 함께 올릴 때는 ZIP으로 묶으세요.

## 다른 사람에게 공유

관리 페이지의 **공유** 탭에서 **공유 QR 보기** 버튼을 누르세요. 방문자용 QR과 링크가 표시되며 관리 경로나 인증 키는 포함되지 않습니다.

PC에서도 생성할 수 있습니다.

```powershell
.\share.ps1 qr -Project my-project
```

방문자는 `/my-project/` 주소에서 파일을 사용합니다. 최신 파일로 계속 연결하려면 HTML 파일명이 아닌 프로젝트 폴더 주소를 공유합니다. 방문자는 여러 명이어도 되지만 관리 링크는 배포하지 않습니다.

## PWA 사용하기

관리 페이지의 **PWA 설정** 탭에서 **PWA로 사용**을 체크하고 앱 이름·짧은 이름·설명·색상을 저장합니다. 파일도 선택했다면 업로드 탭의 **설정 저장 후 업로드**로 한 번에 처리합니다.

PWA 프로젝트는 이후 HTML/HTM만 업데이트합니다. 공용 템플릿과 기존 아이콘을 결합해 `index.html`, 매니페스트, 버전 정보, 서비스 워커를 자동 생성합니다.

- 일반 HTML에는 내용 기반 버전을 자동으로 붙입니다.
- 실행되는 인라인 JavaScript에 유효한 `PWA_BUILD_ID` 선언이 있으면 그 값을 사용합니다.
- 원본 HTML은 그대로 보관하며 생성한 배포본에만 PWA 태그를 연결합니다.
- 서비스 워커 캐시는 프로젝트·배포본별로 구분하고 게임 중 강제로 새로고침하지 않습니다.
- PWA로 전환한 이후 원본은 `projects/프로젝트명/uploads`에서 관리합니다. PC에서 직접 파일을 넣을 때도 이 경로를 사용합니다.
- PWA 체크 해제 시 원본을 유지한 채 일반 HTML·ZIP 모드가 됩니다.
- 임의 프로젝트 서비스 워커 등록은 허용하지 않습니다. PWA 체크로 공용 워커를 사용합니다.
- ZIP에서 전환할 때 사이트 루트의 HTML을 지원합니다. 단일 상위 포장 폴더는 벗기지만, 더 깊은 HTML을 루트로 옮기면 경로가 깨지는 구조는 오류로 안내합니다.

설치가 안 보이면 관리 화면이 아닌 프로젝트 주소를 Chrome 일반 탭에서 열어 확인하세요. 설치 안내와 이미 설치한 앱의 메타정보 갱신 시점은 브라우저가 결정합니다.

## 적용 목록과 정리

**적용 관리** 탭에서 프로젝트별 파일명·수정일·크기와 **현재 적용 / 보관 중**을 확인합니다.

각 버전 카드의 **원본 다운로드**로 업로드했던 HTML·HTM·ZIP을 파일명 그대로 저장할 수 있습니다. PWA 프로젝트도 태그가 추가된 배포본이 아닌 업로드 원본을 받습니다. 다운로드는 적용 버전이나 수정일을 바꾸지 않으며, 관리 인증이 필요합니다. 이미 정리한 파일은 목록에서 다운로드할 수 없습니다.

- **이 파일 적용**: 보관 파일의 수정일을 갱신해 다시 적용합니다.
- **최신만 남기기**: 유지 파일·삭제 파일 목록을 확인한 뒤 오래된 HTML/HTM·ZIP만 삭제합니다.
- 목록이 바뀌면 정리를 중단하고 새 목록을 확인하도록 합니다.
- 이미지·CSS·JavaScript·하위 폴더·PWA 설정·기본 아이콘은 정리 대상이 아닙니다.

이전 ZIP 추출 캐시와 PWA 배포본은 자동 삭제하지 않습니다. 공간이 필요하면 서버를 `stop`한 뒤 `.runtime/zip-cache`, `.runtime/pwa`의 캐시를 정리할 수 있습니다. 인증 파일과 프로젝트 원본은 삭제하지 마세요.

## ntfy는 필요할 때만

서버 시작 알림, 관리 링크 유실 시 복구, 페이지 업데이트 알림이 필요하면 ntfy를 설치한 뒤 구독합니다.

```powershell
.\share.ps1 ntfy              # 구독용 QR 표시, 알림 활성화
.\share.ps1 notify            # 현재 공유 링크 알림 보내기
.\share.ps1 notify -Manage    # 기존 관리 링크를 휴대폰으로 다시 받기
.\share.ps1 notify -Project my-project  # 해당 페이지 링크 수동 발송
.\share.ps1 ntfy -Updates     # 업로드·재적용·PWA 설정 저장 완료 알림 켜기
.\share.ps1 ntfy -NoUpdates   # 자동 업데이트 알림만 끄기
.\share.ps1 ntfy -Disable     # 알림 끄기, 기존 토픽은 보존
```

이 QR은 **ntfy 구독용**입니다. 일반 관리 QR과 다릅니다. 설정된 경우 새 터널 시작 시 알림을 한 번 보내며, 이미 실행 중인 `start`에는 중복 발송하지 않습니다. Cloudflare Quick Tunnel은 URL 변경도 알립니다. 실패한 주소 알림은 재시도하며 프로세스가 유지되는 동안 같은 URL로 연결만 복구되면 알림을 반복하지 않습니다.

ntfy를 끄거나 설치하지 않아도 관리 QR과 관리 페이지는 그대로 사용할 수 있습니다. 기존 사용자가 설정한 알림은 자동으로 해제하지 않습니다.
관리 링크 재전송은 기존 키를 그대로 사용하므로 새로 등록할 필요가 없습니다. 자동 업데이트는 직접 켠 경우에만 전송합니다. 웹에서 성공한 업로드·재적용·PWA 설정 저장이 대상이며, 실패·정리·단순 조회는 제외합니다. PC에 직접 복사한 파일은 자동 감시하지 않으므로 필요하면 `notify -Project 이름`을 실행하세요.
알림 발송 실패가 파일 저장이나 적용을 취소하지는 않습니다. 서버가 공개 주소로 실행 중이어야 링크 알림이 유효합니다.

## 실행·종료와 문제 해결

```powershell
.\share.ps1 start
.\share.ps1 status
.\share.ps1 stop
```

창을 닫아도 백그라운드에서 계속 실행됩니다. PC 종료·절전·인터넷 단절 시 접속은 중단됩니다.

실행 정책 오류는 해당 명령에만 다음 형식을 사용합니다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\share.ps1 start
```

- 설치나 의존성 오류: `setup`, `doctor`로 확인합니다.
- ngrok 인증 오류: `configure`로 Your Authtoken을 다시 저장합니다.
- 포트 충돌: 종료 후 `.\share.ps1 start -Port 8788`로 시작합니다.
- 관리 페이지 404: 일반 루트에서 관리 링크를 찾지 말고 `manage`의 비공개 QR로 연결하세요.
- 관리 API 401: 키가 포함된 관리 링크 전체로 열어야 합니다.
- 파일 목록 변경 오류: 목록을 새로고침한 뒤 작업합니다.
- ZIP 오류: 복사 완료·암호 설정·파일 손상·용량을 확인합니다.
