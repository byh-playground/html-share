1.개요

HTML Share는 내 PC에서 서버를 실행하고, 휴대폰으로 HTML·ZIP을 업로드한 뒤 결과를 확인하는 도구다. 방문자에게는 프로젝트 페이지 링크만 전달한다. 서버 PC가 꺼지거나 절전 상태가 되면 외부 접속도 중단된다.

기본 흐름: 서버 실행 → 관리 QR 스캔 → 프로젝트 선택 → 업로드 후 페이지 열기 → 뒤로 가서 수정본 업로드

직접 만들었거나 신뢰하는 파일만 올린다. 프로젝트별 경로는 있지만 서로 신뢰하지 않는 여러 업로더를 격리하는 서비스는 아니다.

2.설치와 첫 실행

Node.js 22.17 이상을 설치한 뒤 PowerShell에서 저장소를 받는다. Node.js 24 LTS를 권장한다. 

git clone https://github.com/byh-playground/html-share.git
cd html-share
.\share.ps1 setup -Provider cloudflare
.\share.ps1 start -Provider cloudflare

계정 없이 Quick Tunnel 주소와 비공개 관리 QR을 받을 수 있다. 휴대폰 카메라로 QR을 스캔하면 관리 화면이 열린다. 선택한 제공자는 저장되므로 다음부터는 아래 명령만 사용한다. 

.\share.ps1 start
.\share.ps1 status
.\share.ps1 stop

터미널 창을 닫아도 백그라운드 실행은 계속된다. 종료는 stop으로 한다.

PowerShell이 스크립트 실행을 차단할 때 
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\share.ps1 setup -Provider cloudflare

마지막 명령과 옵션을 필요한 작업으로 바꾼다. 시스템 전체 실행 정책을 바꿀 필요는 없다.

3.터널 선택

3.1. Cloudflare Quick Tunnel

.\share.ps1 start -Provider cloudflare

Cloudflare 계정이나 도메인이 필요 없다. 필요한 실행 파일은 자동 설치하며, npm 의존성은 먼저 setup으로 준비해야 한다. 실행 중인 ngrok에서 전환해도 원본과 관리 키는 유지된다.

재생성하면 주소가 바뀔 수 있다. ntfy를 설정하면 새 링크를 받을 수 있다. 예전 도메인으로 설치한 PWA는 새 도메인으로 자동 이전되지 않는다.

터널 프로세스가 종료되면 자동 재시작한다. ntfy 주소 알림 실패는 재시도한다. 프로세스가 유지되는 동안 같은 주소로 연결만 복구되면 알림을 반복하지 않는다.

3.2. ngrok

.\share.ps1 setup -Provider ngrok
.\share.ps1 start -Provider ngrok
  1. 첫 실행의 안내에 따라 ngrok 계정으로 로그인한다.
  2. Your Authtoken에서 토큰 값만 복사한다.
  3. PowerShell에 붙여넣고 Enter를 누른다. 입력이 보이지 않는 것은 정상이다.
  4. 휴대폰에 안내 화면이 나오면 Visit Site를 누른다.

API 키나 명령 전체를 붙여넣지 않는다. 토큰은 로컬에 저장되며, 재설정은 .\share.ps1 configure로 한다. ngrok 토큰과 관리 링크의 인증 키는 별개다.

선택 이력이 없는 설치의 기본값은 ngrok이다. 이후 start는 마지막 제공자를 사용한다. 한도 초기화 후 ngrok으로 돌아가려면 직접 start -Provider ngrok을 실행한다.

3.3. 로컬 전용 실행

npm ci --ignore-scripts
.\share.ps1 stop
.\share.ps1 local
.\share.ps1 manage -Local

공개 목록은 http://127.0.0.1:8787, 업로드는 출력된 로컬 관리 링크로 연다. 외부 공유 중 local만 실행하면 기존 터널은 유지된다. 로컬 전용으로 바꾸려면 먼저 stop을 사용한다.

4.프로젝트 만들기

 
New-Item -ItemType Directory -Path public/my-project

관리 화면의 프로젝트 목록을 새로고침하고 my-project를 선택한다. 공개 주소는 https://터널주소/my-project/다. PC에서 프로젝트 폴더에 HTML·ZIP을 직접 넣어도 된다.

  • 파일명과 무관하게 수정일이 가장 최근인 HTML·HTM·ZIP을 선택한다.
  • HTML과 ZIP의 수정일이 같으면 ZIP이 우선한다.
  • 선택된 최신 ZIP만 압축을 풀어 관련 자원과 함께 제공한다.
  • 공개 루트에는 프로젝트 목록만 표시된다. 루트에 HTML을 직접 넣지 않는다.
  • PWA를 활성화한 프로젝트의 원본 경로는 projects/프로젝트명/uploads로 바뀐다.

5.업로드와 버전 관리

상단에서 선택한 프로젝트를 네 개의 탭이 공통으로 사용한다.

탭 사용법
업로드 HTML·ZIP을 고르고 업로드만 하기 또는 업로드 후 페이지 열기를 누른다.
적용 관리 현재 파일을 확인하고, 보관 파일 재적용·원본 다운로드·최신만 남기기를 실행한다.
PWA 설정 PWA 사용 여부와 앱 정보를 저장한다.
공유 방문자용 페이지 QR 또는 본인용 관리 QR을 표시한다.

같은 이름을 올리면 새 이름으로 보관한다. 완료 전 파일은 게시하지 않는다. 탭을 옮겨도 선택한 파일과 작성 중인 PWA 설정은 유지된다.

  • 원본 다운로드: 업로드했던 HTML·ZIP 그대로 받는다. PWA 가공본이 아니며 적용 상태와 수정일은 바뀌지 않는다.
  • 이 파일 적용: 보관 파일의 수정일을 갱신해 현재 버전으로 선택한다.
  • 최신만 남기기: 삭제 목록을 확인한 뒤 이전 원본 파일을 삭제한다. 필요한 버전은 먼저 다운로드한다.

이미지·CSS·JavaScript와 프로젝트 설정은 원본 정리 대상에서 제외된다. 과거 ZIP 캐시와 PWA 배포본은 자동으로 정리하지 않는다.

6.PWA 설정
  1. 프로젝트를 선택하고 PWA 설정 탭을 연다.
  2. PWA로 사용을 체크한다.
  3. 앱 이름·설명·색상을 입력하고 저장한다.
  4. 이후 HTML·HTM을 업로드해 업데이트한다.

공용 템플릿으로 매니페스트와 서비스 워커를 생성한다. 원본은 그대로 보존하며, PWA 프로젝트는 ZIP 업로드를 받지 않는다. 체크를 해제해도 원본과 설정은 유지된다.

일반 HTML은 내용 해시로 버전을 만든다. 실행되는 인라인 JavaScript의 PWA_BUILD_ID 문자열 상수도 사용할 수 있다. 임의로 업로드한 서비스 워커 등록은 차단되므로 공용 PWA 기능을 사용한다.

설치 안내는 브라우저 정책에 따라 다르다. HTTPS 프로젝트 주소를 Chrome 일반 탭에서 열어 확인한다. 도메인이 바뀌면 설치 앱과 브라우저 저장 데이터는 자동 이전되지 않는다.

7.QR과 관리 링크

관리 QR은 본인만, 프로젝트 QR은 방문자에게. 관리 링크는 파일 업로드·설정·정리 권한을 포함한다. 

.\share.ps1 manage
.\share.ps1 qr -Project my-project
.\share.ps1 manage -Local

관리 페이지의 공유 → 내 기기 연결에서도 관리 QR을 볼 수 있다. 재시작은 인증 키를 바꾸지 않는다. 터널 도메인이 바뀌면 전체 주소는 달라진다.

관리 링크 자체를 새로 발급하고 싶을 때 
.\share.ps1 manage -Rotate

서버 실행 중 사용한다. 이전 키·링크·QR은 무효화되고 새 관리 주소가 표시된다. 프로젝트 공개 주소는 유지된다.

공개 목록에는 관리 링크가 없다. 관리 API에는 별도 인증이 필요하다. 다만 모든 프로젝트가 같은 출처를 공유하므로 악성 HTML을 안전하게 격리하는 구조는 아니다.

8.ntfy 알림

필수 기능은 아니다. 주소 유실·서버 재시작·Quick Tunnel 주소 변경 때 새 링크를 받기 위한 선택 사항이다. 

.\share.ps1 ntfy
.\share.ps1 notify -Manage
.\share.ps1 notify -Project my-project
.\share.ps1 ntfy -Updates
.\share.ps1 ntfy -NoUpdates
.\share.ps1 ntfy -Disable

첫 ntfy 실행에서 표시되는 구독 QR로 Android ntfy 앱에 토픽을 등록한다. 기존 토픽이 있으면 재사용한다. notify -Manage는 키를 재발급하지 않고 현재 링크를 다시 보낸다.

-Updates는 웹 업로드·재적용·PWA 설정 저장 성공 시 알림을 추가한다. 시작·주소 변경 알림에는 필요하지 않다. PC에 직접 복사한 파일은 자동 알림 대상이 아니며 notify -Project로 알린다.

관리 버튼이 포함된 알림은 관리 링크를 외부 ntfy 서비스로 전달한다. 토픽은 본인만 보관한다.

9.명령어 모음

전체 옵션과 예시는 .\share.ps1 help에서 한글로 확인한다. -Help, -h, Get-Help .\share.ps1 -Full도 지원한다.

명령 역할
setup [-Provider cloudflare|ngrok] 의존성과 터널 설치
doctor 환경·설정 확인
start [-Provider …] [-Port 8787] 공유 시작·제공자 전환
local [-Port 8787] 로컬 서버 실행·재사용
status / stop 상태 확인 / 종료
configure ngrok 토큰 재설정
manage [-Local 또는 -Rotate] 관리 주소 확인 / 로컬 주소 / 키 재발급
upload manage의 호환 명령
qr [-Project 이름] 관리 또는 프로젝트 QR
pwa -Project 이름 해당 프로젝트 PWA 활성화
ntfy [-Topic 이름] 알림 구독 구성
notify [-Manage 또는 -Project 이름] 현재 링크 수동 전송

명령 앞에는 .\share.ps1을 붙인다. 공백이 있는 프로젝트 이름은 따옴표로 감싼다. 포트 변경은 stop 후 실행한다.

10.문제 해결
공개 목록에서 업로드 페이지가 보이지 않는다

정상이다. 공개 목록은 프로젝트 링크만 제공한다. manage 또는 manage -Local로 비공개 관리 주소를 확인한다.

ngrok 한도에 걸렸다

start -Provider cloudflare로 전환할 수 있다. 새 도메인 링크로 접속해야 한다. 관리 URL 재발급은 ngrok 한도를 초기화하지 않는다.

휴대폰에서 예전 버전이 보인다

현재 관리 페이지의 적용 파일을 확인한다. 터널 주소가 바뀌었다면 최신 ntfy 링크로 연다. 이전 주소의 설치 PWA가 오프라인 캐시를 보여 줄 수 있다. 앱 내부에 표시되는 날짜는 업로드 시각과 다를 수 있다.

큰 ZIP 업로드가 실패한다

Cloudflare를 통한 요청은 업로드 크기 제한을 받는다. PC에서 manage -Local로 올린다. 서버의 기본 업로드 한도는 256 MiB이며 ZIP 내부 파일 수·압축 해제 크기 등의 별도 검증도 적용된다.

로컬 주소를 휴대폰에서 열 수 없다

127.0.0.1은 접속한 기기 자신을 가리킨다. 휴대폰에서는 외부 터널 주소의 QR이나 링크를 사용한다.

다른 프로젝트에 파일을 올리고 싶다

PC의 public 아래에 프로젝트 폴더를 만들고 관리 화면의 목록을 새로고침한다. 상단에서 대상 프로젝트를 선택한다.
